# Lab 01 — 웹 서버 1대가 죽어도 살아있는 서비스

## 상황

작은 웹 서비스를 AWS에서 운영하고 있다.

현재는 EC2 인스턴스 한 대에서 애플리케이션을 실행하고 있으며, 사용자는 해당 서버에 직접 접속한다.

문제는 서버 한 대가 재부팅되거나 애플리케이션 프로세스가 죽으면 서비스 전체가 중단된다는 점이다.

운영팀은 다음 요구사항을 제시했다.

## 요구사항

### 기능

- HTTP 요청을 받을 수 있어야 한다.
- `/health` 요청은 정상 상태일 때 HTTP 200을 반환해야 한다.
- 어떤 서버가 요청을 처리했는지 응답에서 구분할 수 있어야 한다.

### 가용성

- 애플리케이션 서버 한 대가 죽어도 사용자는 계속 서비스를 이용할 수 있어야 한다.
- 단일 Availability Zone 장애 가능성도 고려한다.
- 비정상 서버에는 새 요청이 전달되지 않아야 한다.

### 확장성

- 현재는 큰 트래픽이 없으므로 최소한의 서버만 유지한다.
- 이후 서버 수를 늘릴 수 있는 구조여야 한다.

### 보안

- 애플리케이션 서버는 인터넷 전체에서 애플리케이션 포트로 직접 접근할 수 없어야 한다.
- 외부 사용자가 접근해야 하는 진입점만 Public traffic을 허용한다.

### 비용

- 학습용이므로 가능한 작은 인스턴스를 사용한다.
- 불필요한 리소스는 실습 직후 제거한다.

## 제한사항

이번 Lab에서는 아래 서비스 범위 안에서 먼저 해결한다.

- EC2
- Security Group
- Application Load Balancer
- Target Group
- Availability Zone / Subnet

Auto Scaling Group은 **아직 필수로 사용하지 않는다.**

먼저 고정된 여러 EC2 인스턴스로 고가용성 구조를 이해한 뒤 다음 Lab에서 ASG를 추가한다.

## 네가 결정해야 할 것

정답을 검색하기 전에 아래 질문에 답한다.

1. 사용자는 무엇을 통해 서비스에 접근해야 하는가?
2. EC2는 몇 대가 필요한가?
3. EC2들을 같은 AZ에 둘 것인가, 여러 AZ에 나눌 것인가?
4. Load Balancer는 왜 필요한가?
5. 어떤 Load Balancer를 선택할 것인가?
6. Health Check는 어떤 경로와 포트로 설정할 것인가?
7. Load Balancer용 Security Group과 EC2용 Security Group은 어떻게 나눌 것인가?
8. EC2의 inbound source를 IP 대역으로 열 것인가, 다른 Security Group을 참조할 것인가?
9. 서버 한 대가 죽었을 때 실제로 무엇이 일어날 것이라고 예상하는가?

답은 [`architecture.md`](./architecture.md)에 먼저 작성한다.

## 구축 목표

구축이 완료되면 사용자가 하나의 endpoint로 요청을 보내고, 뒤의 여러 애플리케이션 서버 중 정상 서버가 요청을 처리해야 한다.

애플리케이션은 최소한 다음 응답을 제공한다.

```text
GET /

hello from <hostname-or-instance-id>
```

```text
GET /health

200 OK
```

간단한 Nginx, Python HTTP server, FastAPI 등 어떤 방식으로 구현해도 된다.

## 검증

### 1. 기본 분산 확인

Load Balancer endpoint로 여러 번 요청한다.

```bash
curl http://<load-balancer-dns>
```

여러 서버에서 응답이 오는지 관찰한다.

### 2. 직접 접근 차단 확인

EC2에 public IP가 존재한다면 EC2의 애플리케이션 포트로 직접 요청해본다.

```bash
curl http://<ec2-public-ip>:<app-port>
```

설계 의도대로 차단되는지 확인한다.

### 3. 애플리케이션 장애

EC2 한 대에서 애플리케이션 프로세스를 종료한다.

예:

```bash
sudo systemctl stop nginx
```

확인할 것:

- Target Group에서 해당 인스턴스가 `unhealthy`로 변경되는가?
- Load Balancer endpoint는 계속 응답하는가?
- 비정상 인스턴스로 새 요청이 전달되는가?

### 4. 인스턴스 장애

EC2 한 대를 Stop 또는 Terminate한다.

확인할 것:

- 사용자가 계속 서비스를 사용할 수 있는가?
- 현재 구조가 서버를 자동으로 복구하는가?
- 자동 복구되지 않는다면 무엇이 부족한가?

이 마지막 질문이 다음 Lab의 출발점이다.

## 장애 실험 전 예상 작성

실험 전에 `architecture.md`에 다음을 먼저 적는다.

- 서버 1대의 프로세스가 죽으면 어떻게 될까?
- 서버 1대 자체가 죽으면 어떻게 될까?
- 한 AZ 전체가 장애 나면 어떻게 될까?
- Load Balancer 자체는 단일 장애점인가?

실제 결과와 비교한다.
