# ADM-01 kubeadm 클러스터 구축

> 분류: **CKA 필수** · 연결/선행: **플랫폼** · [기본 학습](../../08-independent/README.md) · [환경 기준](../../07-cka-preview/ENVIRONMENT.md)

## Overview — 왜 배우는가?

kubeadm init/join, kubelet, CRI, CNI 순서와 정상 판정을 이해한다. 기존의 관련 실습과 연결해, 객체 조회에 그치지 않고 **컴포넌트의 판단 → Linux/Runtime의 실행 → 상태·로그·이벤트 증거**를 이어서 설명한다.

## 선수 지식과 동작 원리

기존 08-independent/PLATFORM.md의 별도 1.34 VM 과정을 그대로 수행한다. CNI 설치 전후 Ready와 CoreDNS 변화를 구분한다.

## 예측 후 관찰

실행 전에 (1) 예상 상태, (2) 이 상태를 책임지는 컴포넌트, (3) 검증할 증거를 먼저 적는다. 아래 명령은 Linux/bash 셸에서 실행한다. 리소스가 이미 만들어져 있어야 하는 명령은 연결된 이전 단계를 먼저 수행한다.

```bash
kubectl get nodes -o wide
kubectl -n kube-system get pods -o wide
sudo systemctl status kubelet --no-pager
sudo crictl info
```

출력이 비어 있거나 오류가 나면 도구 부재·리소스 미준비·실제 장애를 구분한다. 비어 있는 값이나 실패를 정상 동작의 증거로 사용하지 않는다.

## 장애 가설 → 증거 → 복구

NotReady 시 CRI, kubelet 로그, Pod CIDR 및 CNI 설치 상태를 확인한다.

가설과 관찰 결과가 일치하는지 기록하고, 최소한의 변경으로 복구한 뒤 **처음과 같은 명령/요청**으로 성공을 확인한다. 이 문서는 안전한 관찰 순서가 기본이며, 위험한 장애 주입은 명시한 별도 VM에서만 수행한다.

## 환경 제약 및 정리

기존 Rocky 1.27 클러스터에서는 kubeadm init/reset을 실행하지 않는다. 전용 VM 필수.

- Kubernetes 1.27.2에서 실제 실행한 내용과 최신 버전의 공식 설명을 구분한다.
- 이 문서 작성만으로 사용자 VM 실행 완료를 뜻하지 않는다.
- 실습 완료 기록: [CHECKPOINTS](../../08-independent/CHECKPOINTS.md).
