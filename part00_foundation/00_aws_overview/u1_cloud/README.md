# u1. 클라우드란 무엇인가

## 지도 확인

이 유닛은 AWS의 개별 서비스를 배우기 전에, 클라우드가 해결하려는 문제와 AWS가 어떤 종류의 서비스를 제공하는지 큰 그림을 잡는 단계다.

이후 학습할 EC2, S3, RDS, VPC, Lambda 등의 서비스는 모두 이 큰 그림 안에서 이해한다.

## 개념

### 1. 클라우드 컴퓨팅이란

클라우드 컴퓨팅은 서버, 스토리지, 데이터베이스, 네트워크 같은 IT 자원을 직접 구매하고 설치하는 대신, 필요할 때 네트워크를 통해 빌려 사용하고 사용량에 따라 비용을 지불하는 방식이다.

전통적인 온프레미스 환경에서는 서버를 직접 구매하고 데이터센터에 설치한 뒤 운영해야 한다.

```text
On-Premises

회사
 └─ 직접 구매한 서버
     ├─ CPU
     ├─ Memory
     ├─ Disk
     └─ Network
```

클라우드에서는 클라우드 사업자가 물리 인프라를 운영하고 사용자는 필요한 자원을 요청해서 사용한다.

```text
Cloud

사용자
  ↓ 요청
Cloud Provider
  ├─ Compute
  ├─ Storage
  ├─ Database
  ├─ Network
  └─ Managed Services
```

AWS는 이러한 자원을 제공하는 Cloud Provider 중 하나다.

### 2. 왜 클라우드를 사용하는가

#### 빠른 프로비저닝

물리 서버를 구매하면 주문, 배송, 설치까지 시간이 필요하지만 클라우드에서는 몇 분 안에 서버를 생성할 수 있다.

#### 탄력적인 확장

서비스 부하가 증가하면 더 큰 서버로 변경하거나 서버 수를 늘릴 수 있다.

```text
사용자 증가
    ↓
서버 1대
    ↓
서버 여러 대
```

반대로 사용량이 줄면 자원을 줄일 수도 있다.

#### 사용량 기반 비용

필요한 자원을 필요한 기간 동안 사용한다. 다만 항상 클라우드가 더 저렴한 것은 아니며, 장기적이고 예측 가능한 워크로드에서는 비용 구조를 따져봐야 한다.

#### 관리형 서비스

AWS는 단순한 가상 서버뿐 아니라 데이터베이스, 메시지 큐, 모니터링 등 다양한 관리형 서비스를 제공한다.

예를 들어 직접 PostgreSQL 서버를 설치해서 운영할 수도 있지만 Amazon RDS를 사용하면 AWS가 운영 작업의 상당 부분을 대신 수행한다.

### 3. AWS에서 자주 만나게 될 자원

```text
Compute      → EC2, Lambda, ECS
Storage      → S3, EBS, EFS
Database     → RDS, Aurora, DynamoDB
Networking   → VPC, ELB, Route 53
Security     → IAM, KMS
Monitoring   → CloudWatch, CloudTrail
```

현재는 이름을 외우지 않는다. 이후 각각을 직접 사용하면서 역할을 연결한다.

## SAA 연결

SAA는 AWS 서비스의 정의를 단순 암기하는 것보다, 주어진 요구사항에 어떤 서비스를 선택해야 하는지를 묻는 문제가 중심이다.

예를 들어 다음과 같은 질문을 판단할 수 있어야 한다.

- 서버를 직접 운영해야 하는가, 관리형 서비스를 사용할 수 있는가?
- 트래픽이 증가했을 때 어떻게 확장할 것인가?
- 장애가 발생해도 서비스를 계속 제공하려면 어떻게 구성할 것인가?
- 비용을 낮추기 위해 어떤 구조를 선택할 것인가?

따라서 앞으로는 항상 다음 질문을 함께 생각한다.

> 이 서비스는 어떤 문제를 해결하며, 다른 선택지 대신 왜 이 서비스를 사용하는가?

## 예제

아직 AWS 리소스를 생성하지 않는다.

다음 두 시스템을 비교해보자.

### A. 직접 운영

```text
Internet
   ↓
직접 구매한 Server
   ↓
직접 설치한 PostgreSQL
```

### B. AWS 사용

```text
Internet
   ↓
EC2
   ↓
RDS
```

두 시스템 모두 웹 애플리케이션을 실행할 수 있지만, 서버 조달 방식과 운영 책임의 범위가 다르다.

이 차이는 이후 EC2와 RDS를 배우면서 다시 다룬다.

## 유제

### 이해

1. 회사가 새 웹 서비스를 출시하려고 한다. 예상 사용자가 얼마나 될지 모르는 상황에서 물리 서버를 먼저 대량 구매하는 것과 클라우드를 사용하는 것의 차이를 설명하라.
2. 클라우드를 사용한다고 해서 항상 비용이 더 저렴하다고 말할 수 없는 이유를 생각해보라.
3. EC2와 RDS가 모두 AWS 서비스인데도 왜 하나는 서버에 가깝고 다른 하나는 관리형 서비스에 가까운지 예상해보라.

### 판단

다음 상황에서 클라우드의 어떤 특징이 도움이 되는지 적어보자.

1. 이벤트 때문에 하루 동안 트래픽이 평소의 10배로 증가한다.
2. 개발팀이 테스트 서버를 오늘 안에 하나 필요로 한다.
3. 트래픽이 거의 없는 개발 서버가 밤에도 계속 실행되고 있다.

## 포트폴리오 연결

앞으로 하나의 웹 서비스를 다음과 같이 단계적으로 발전시킨다.

```text
Local Application
      ↓
EC2
      ↓
ALB + Multiple EC2
      ↓
RDS
      ↓
Docker / ECS
      ↓
Terraform
      ↓
CI/CD + Monitoring
```

이 유닛에서는 아직 구현하지 않는다. 이후 각 서비스를 배우면서 이 구조를 하나씩 만든다.
