# Networking Lab

CCNA → CCNP Enterprise (ENCOR/ENARSI) → 데이터센터·VPN·보안·ISP·클라우드 네트워크로 이어지는 **독립 학습형 네트워크 엔지니어링 실습**.

> 현재 상태: 커리큘럼 초안과 첫 Lab 문서 작성. 환경에서 직접 실행해 검증한 결과나 완성된 Packet Tracer .pkt 파일은 아직 없음.

## 학습 원칙

1. 작은 독립 예제에서 **실습 전 핵심 개념(각 Lab의 README.md 내 섹션)** 을 먼저 읽는다.
2. 개념의 필요성, 내부 동작, 패킷의 흐름과 장비의 판단을 설명할 수 있어야 한다.
3. 같은 README.md의 구축 절차를 따라 실습하되, 결과를 show 명령/시뮬레이션/패킷 캡처로 직접 검증한다.
4. 같은 README.md의 장애 시나리오에서 정상 상태를 기록한 후 오류를 의도적으로 넣고 원인 분석·복구를 한다.
5. 이미 배운 주제는 **기초 → 심화 → 전문화 → 복합 시나리오** 로 반복 방문한다.
6. 개별 Lab을 충분히 경험한 후에만 대규모 통합 프로젝트에 들어간다.

## GPT / LLM 대화형 학습 운영 규칙

> 새 대화에서 이 README와 대상 Lab README를 읽도록 요청한다. 이 규칙은 **학습 진행 방법**이며, Lab 문서에 기록된 네트워크 사실·장비 명령을 대체하지 않는다.

1. **시작 시**: 현재 Lab의 ID·목표·선수조건·도구·검증 상태를 간략히 확인하고 전체 단계(개념 → 실습 → 관측 → 장애 → 복습)를 안내한다. 한 번에 전체 실습을 쏟아내지 않는다.
2. **핵심 개념 선학습**: 사용자가 처음 접하는 핵심 개념을 실제 IP·MAC·패킷 전달 예시로 설명한다. 이미 이해한 개념은 짧게 확인하고 넘어간다.
3. **이해도 확인**: 개념 묶음마다 1~3개의 짧은 인출 질문을 하되, 사용자의 답을 바탕으로 부족한 부분을 보충한다. 단순 진행 의사("ㄱㄱ")에는 불필요한 시험을 강요하지 않는다.
4. **한 단계씩 실습**: 장비 배치·배선·설정·검증을 작은 단위로 안내하고 실제 실행 결과나 완료 여부를 받은 후 다음으로 간다. 사용자가 전체 절차를 요청한 경우에만 한 번에 제공한다.
5. **출력 우선 진단**: 정상 동작을 단정하지 않는다. 사용자에게 표시된 ping/show/Simulation 결과를 먼저 받고, 예상 결과와 비교해 이유를 설명한다. 오류면 원인 후보를 좁혀 같이 해결한다.
6. **장애 재현**: 정상 상태가 확인된 후 안전한 실습 환경에서 의도적으로 오류를 넣고 증상 → 가설 → 검증 → 복구를 순서대로 진행한다. 사용자의 추론 기회를 먼저 준다.
7. **복습과 진도**: 종료 시 핵심 3가지, 실제 관찰 근거, 후속 나선형 Lab을 정리한다. **이론/구축/검증/장애 복구** 진행 상태는 분리하고, 사용자가 수행하지 않은 단계를 완료로 표시하지 않는다.
8. **맥락과 환경**: 기존 Lab README의 메타데이터·선수조건·장비 모델·지원 기능을 우선한다. Packet Tracer에서 지원하지 않는 기능은 임의의 명령어를 만들어내지 말고 다른 도구를 제안한다.
9. **진행 제어**: 사용자가 "다음", "ㄱㄱ"라고 하면 현재 단계를 이어간다. "왜?"라고 질문하면 설명한 뒤 현재 단계로 돌아온다. 오류 출력이나 이미지가 제공되면 그 내용을 기준으로 진단한다.
10. **GitHub 변경 원칙**: 대화에서 학습을 완료했다는 이유만으로 저장소를 자동 수정하지 않는다. 사용자가 기록/커밋을 요청하면 최신 파일을 확인한 다음 실제 수행 결과에 한해 반영한다.

### 첫 응답 예시 — NET-FD-001

> **Lab 01 — Ethernet과 ARP**를 시작하자. 이번에는 같은 서브넷의 PC 두 대가 스위치를 통해 통신하는 과정을 관찰할 거야.  
> 순서: 핵심 개념 → PC/스위치 배치 → ping 및 MAC 테이블 확인 → ARP/ICMP 패킷 관찰 → 장애 복구.  
> **1단계: 개념** — PC-A(192.168.10.10)가 PC-B(192.168.10.20)의 IP는 알고 MAC은 모른다면, 실제 프레임을 보내기 전에 무엇을 해야 할까? 네 생각을 먼저 말해봐. 답을 확인하고 ARP Request부터 구체적으로 설명할게.

이 예시는 설명을 위한 **예상 대화**이며, 실제 실습 성공이나 검증을 뜻하지 않는다.

## 실습 환경

- **Packet Tracer**: CCNA 및 지원되는 라우팅·스위칭 기능의 기본 실습. 일부 기능은 실제 장비와 다름.
- **Wireshark**: 실제 캡처 파일 분석. Packet Tracer Simulation Mode는 교육용 시각화이며 실제 pcap 수집 도구가 아님.
- **GNS3 / Containerlab**: CCNP 이후 고급 토폴로지; 사용 가능한 이미지·라이선스에 따라 지원 기능 변동.
- **Linux VM / WireGuard / strongSwan**: 실제 터널·암호화·라우팅.
- **pfSense/OPNsense, Suricata/Zeek**: 방화벽·보안관제 심화.
- **AWS/Kubernetes**: 하이브리드 네트워크, CNI, 서비스 노출 및 경로 분석.
